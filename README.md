# PIERROT — LLM 환각 검증 시스템

LLM 답변을 **검증 가능한 주장(claim) 단위로 분해**하고, 각 주장을 공시·주가 등 실제 데이터와
대조해 주장별 신뢰 판정을 붙이는 시스템입니다.

> 삐에로는 웃는 분장 뒤에 진짜 표정을 숨깁니다.
> LLM도 틀린 답을 자신 있게 말합니다. PIERROT는 그 가면을 벗겨 답변의 실제 근거 여부를 드러냅니다.

---

## 현재 상태

**0단계 완료 — 공통 기반(설정, 응답 캐시, 토큰·비용 로거)이 동작합니다.**
검증 가능한 주장 분해 로직은 1단계에서 만듭니다.

진행 상황은 아래 [로드맵](#로드맵)에서 확인할 수 있습니다.

---

## 이 프로젝트가 증명하려는 것

"환각 검증기를 만들었다"가 아니라 **"검증기 자체의 성능을 숫자로 증명했다"** 입니다.

그래서 비교 대상을 3단으로 둡니다.

| 구분 | 방식 | 역할 |
|---|---|---|
| 베이스라인 ① | 한국어 NLI 모델 단독 | 전통적 방식. 숫자·날짜에 약하다는 것을 실측으로 보여줍니다 |
| 베이스라인 ② | LLM-as-judge (`gpt-4o-mini`) | "요즘은 LLM에 직접 물어보면 되지 않나"라는 반론에 답합니다 |
| 개선안 | 도구 기반 검증 (DART, 주가 계산) | 이 프로젝트의 주장 |

베이스라인이 하나뿐이면 "약한 상대와 비교했다"는 반론을 막을 수 없기 때문입니다.

## 동작 흐름

```
사용자 질문: "삼성전자 3분기 영업이익과 주가 흐름 요약해줘"
        ↓
[1] 답변 생성 (generator)        RAG 기반. 로컬 Ollama gemma3:4b
        ↓
[2] 주장 분해 (extractor)        검증 가능한 최소 문장 단위로 분리
        ↓
[3] 검증 에이전트 (verifier)     주장 유형별로 도구를 선택해 확인
        · 숫자 주장  → DART 공시 API
        · 주가 주장  → OHLCV 스냅샷 조회 후 직접 계산
        · 서술 주장  → 근거 문서와 의미 비교 (NLI)
        ↓
[4] 판정                         SUPPORTED / CONTRADICTED / UNVERIFIABLE
        ↓
[5] 최종 출력 (reporter)         원본 답변에 주장별 신뢰 표시 부착
```

## 기술 구성

| 자리 | 사용 기술 | 실행 위치 |
|---|---|---|
| 답변 생성 | Ollama `gemma3:4b` + RAG | 로컬 서버 (무료) |
| 주장 분해 / 검증 판단 | OpenAI `gpt-4o-mini` | OpenAI API |
| 에이전트 | LangChain + LangGraph | 로컬 |
| 검증 도구 | DART 공시 API, FinanceDataReader, `Huffon/klue-roberta-base-nli` | 로컬 (무료) |
| 평가 | 직접 구축한 테스트셋 + 정밀도 / 재현율 / 오탐률 | 로컬 (순수 파이썬) |
| 서빙 | FastAPI | 로컬 |
| 운영 | 응답 캐시, 토큰·비용 로거, LangSmith 트레이싱 | 로컬 |

### 설계 원칙 두 가지

1. **평가 재현성** — `evaluation` 모듈은 LangChain에 의존하지 않습니다. 주가 데이터도 실행 중에
   외부 조회를 하지 않고 로컬 스냅샷만 사용합니다. 프레임워크나 외부 사이트가 바뀌어도
   과거 평가 결과를 다시 뽑을 수 있어야 하기 때문입니다.
2. **비용 통제** — 월 예산 $5 안에서 운영합니다. 디스크 응답 캐시와 토큰·비용 로거를
   0단계부터 필수 구성 요소로 둡니다.

## 알려진 한계

- 테스트셋은 정상 답변에 **오류를 의도적으로 주입**해 만듭니다. 정답 라벨이 정확한 대신,
  실제 LLM이 내는 환각과 분포가 다릅니다. 이 점을 감안해 `generator`가 실제로 만들어 낸
  환각 샘플도 소수 수집해 보조 검증 세트로 함께 사용할 예정입니다.
- 검증 도구가 금융 도메인(DART 공시, 국내 주가)에 맞춰져 있습니다. 다른 도메인에 적용하려면
  `tools` 모듈을 교체해야 합니다. 파이프라인 구조 자체는 도메인에 독립적입니다.

## 실행 준비

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"

cp .env.example .env     # 실제 키를 채웁니다 (.env 는 커밋되지 않습니다)
```

Ollama는 원격 서버의 `127.0.0.1:11434`에만 바인딩되어 있어, 사용 전 SSH 터널이 필요합니다.

```bash
ssh -N -L 11434:127.0.0.1:11434 ai-server
```

### 동작 확인

```bash
.venv/Scripts/python.exe -m pytest              # 단위 테스트 (API 호출 없음, 과금 없음)
.venv/Scripts/python.exe scripts/check_setup.py # 실제 연결 확인 (약 $0.00001 과금)
```

`check_setup.py`는 네 가지를 실제로 실행해 확인합니다.

1. 설정 로딩 (`.env`)
2. Ollama `gemma3:4b` 응답
3. OpenAI 실제 호출 1회 + 비용이 `logs/cost.jsonl`에 기록되는지
4. 같은 프롬프트 재호출 시 캐시로 처리되어 과금되지 않는지

과금을 피하려면 `--skip-openai` 를 붙입니다.
