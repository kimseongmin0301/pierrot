# PIERROT — AI 답변에 빨간 펜을 대는 검증기

AI가 쓴 금융 리포트를 문장 단위로 쪼개고, 문장마다 **금융감독원 공시와 실제 주가를
직접 찾아본 뒤**, 틀린 문장에 표시를 붙입니다.

> 삐에로는 웃는 분장 뒤에 진짜 표정을 숨깁니다.
> AI도 틀린 답을 자신 있게 말합니다. PIERROT는 그 가면을 벗깁니다.

---

## 이런 걸 잡습니다

AI(`gemma3:4b`)에게 삼성전자 실적을 물었더니 이렇게 답했습니다.

```
AI가 말한 것:  삼성전자 2024년 3분기 영업이익은 6조 1,879억 원입니다.
실제 공시:                                    9조 1,833억 원
                                              ───────────────
                                              3조 차이
```

**3조가 틀렸는데 AI는 아주 자신 있게 씁니다.** 읽는 사람은 알 방법이 없습니다.
금융·의료처럼 숫자가 틀리면 안 되는 곳에서 AI를 그대로 못 쓰는 이유가 이것입니다.

PIERROT에 같은 답변을 넣으면 이렇게 나옵니다.

```
삼성전자는 2024년 3분기에 6조 1,879억 원의 영업이익을 기록했습니다. [모순]
매출은 68조 423억 원이었습니다. [모순]
```

표시마다 **왜 틀렸는지**가 붙습니다.

```
"삼성전자 2024년 3분기 영업이익 실제 연결 9조 1,833억원 / 별도 4조 5,049억원,
 주장 6조 1,879억원 (허용 오차 ±309억원) → 어느 기준과도 맞지 않습니다"
```

---

## 어떻게 동작하나

```
AI 답변  "삼성전자 3분기 영업이익은 6조 1,879억 원이고, 주가는 올랐습니다."
   │
   ├─ 1. 문장 쪼개기      검증할 수 있는 최소 단위로 나눕니다
   │                      → "영업이익은 6조 1,879억 원이다"
   │                      → "주가는 올랐다"
   │
   ├─ 2. 빠진 맥락 채우기  "누가" "언제"를 답변 앞쪽에서 찾아 넣습니다
   │                      → "삼성전자의 2024년 3분기 영업이익은 ..."
   │
   ├─ 3. 담당 정하기      문장마다 어느 자료를 봐야 하는지 고릅니다
   │                      → 실적 문장은 공시로, 주가 문장은 시세로
   │
   ├─ 4. 대조하기         실제 자료를 조회해 숫자를 직접 비교합니다
   │
   └─ 5. 표시 붙이기      원본 답변 위에 [모순] / [확인 불가]를 붙입니다
```

중요한 설계 하나. **AI는 문장을 쪼개고 뜻을 읽는 데만 씁니다.
숫자 비교와 판정은 전부 파이썬이 합니다.** AI에게 숫자를 비교시키면 틀립니다.
이건 짐작이 아니라 측정으로 확인했습니다(아래 참고).

## 그래서 이 검증기는 얼마나 정확한가

"만들었다"가 아니라 **"얼마나 맞히는지 숫자로 증명했다"**가 이 프로젝트의 핵심입니다.

정답을 아는 문제 **500개**를 만들어 시험했습니다. 정답 라벨은 사람이 붙이지 않고
**공시 데이터에서 직접 생성**했습니다. 그래서 라벨 자체를 의심할 필요가 없습니다.

| 방식 | 틀린 문장을 잡아낸 비율 | 맞는 문장을 틀렸다고 한 비율 |
|---|---|---|
| **PIERROT (자료 대조)** | **100%** | **0%** |
| AI에게 직접 물어보기 | 46.2% | 31.1% |
| 문장 유사도 모델(NLI) | 15.4% | 45.3% |

실제 AI가 쓰는 방식(어림수, "억" 단위, "4월 중순" 같은 모호한 날짜)으로 만든
어려운 문제 200개 기준입니다. **비교 대상을 두 개 둔 이유**는, 하나뿐이면
"약한 상대와 비교했다"는 반론을 막을 수 없기 때문입니다.

### 다만 이 100%를 그대로 믿으면 안 됩니다

테스트 문제는 **자료가 반드시 있는 조건**으로 만들었습니다. 실제 AI 답변은 다릅니다.
그래서 진짜 답변 10건(문장 94개)을 그대로 넣어 따로 쟀습니다.

| | 건수 | |
|---|---|---|
| 틀렸다고 잡아낸 문장 | **41** | 이 중 39건은 숫자를 직접 비교해 증명 |
| 맞다고 확인한 문장 | **0** | AI가 말한 수치 중 맞는 게 하나도 없었습니다 |
| 판정하지 못한 문장 | 53 | 사유를 전부 기록했습니다 |

**판정 가능 비율은 53.9%입니다**(미래 전망 문장 제외 기준, 전체 기준으로는 43.6%).
절반쯤밖에 못 봅니다. 숨길 일이 아니라 **어디를 고쳐야 하는지 알아내는 출발점**입니다.

### 판정 못 한 53건을 원인별로 전부 분류했습니다

"53건을 못 했다"는 말은 아무것도 알려주지 않습니다. 원인에 따라 고칠 곳이 완전히 다릅니다.

| 원인 | 건수 | 고칠 수 있나 |
|---|---|---|
| 미래 전망·투자 권고 문장 | 18 | ✗ 애초에 참·거짓을 가릴 수 없음 |
| 공시 주요계정에 없는 항목 | 9 | ○ 자료를 더 붙이면 됨 |
| 문장 뜻 비교의 한계 | 8 | △ 검색 방식 교체 후보 |
| 인과·변동성 등 숫자로 못 재는 문장 | 5 | ✗ 검증 대상 아님 |
| 회사가 그 단위로 공시하지 않음 | 5 | ✗ 공시의 한계 |
| 나머지 | 8 | — |

**이 프로젝트에서 가장 쓸모 있는 산출물이 이 표입니다.**
판정 가능 비율의 이론적 상한이 100%가 아니라 **약 75%**라는 것이 여기서 나옵니다.
94건 중 24건(25.5%)은 애초에 참·거짓을 가릴 수 있는 종류의 문장이 아닙니다.

### 일부러 함정을 심은 글 20건으로 다시 시험했습니다

테스트셋 500건과 실제 AI 답변만으로는 안 보이는 구멍이 있습니다. 그래서
**사람이 함정을 설계한 글 20건**(문장 45개)을 따로 만들어 넣었습니다.
연결/별도 뒤집기, 인과, 최상급, 두 개의 비교 기준, 회사명 누락 같은 것들입니다.

| | 처음 | 고친 뒤 |
|---|---|---|
| 판정이 맞은 문장 | 41/45 (91.1%) | **44/45 (97.8%)** |
| **거짓인데 "근거 있음"** (가장 위험) | **2건** | **0건** |
| 거짓인데 놓침 | 2건 | **1건** |
| 판정 가능 비율 | 68.9% | **71.1%** |

남은 1건은 "전년과 같은 수준"인데 실제로는 +7.1%였던 문장입니다. 억지로
한쪽으로 몰지 않고 **실제 변동률을 적어 확인 불가로 둡니다.** 가르지 못한 것을
가른 척하는 것보다 낫다고 판단했습니다.

이 20건이 **다섯 가지 결함을 새로 찾아냈습니다.** 둘은 거짓을 참으로 만드는
오탐이었고, 셋은 사유가 뭉개져 "왜 못 봤는지" 알 수 없게 만드는 문제였습니다.
아래 [측정이 잡아낸 오류들](#측정이-잡아낸-오류들)에 있습니다.

### 남이 만든 테스트셋은 **라벨부터 의심했습니다**

가상 종목 샘플 100건과 정답표를 받았습니다. 정답이 진짜 정답인지는
아무도 확인하지 않은 상태였습니다. **라벨을 의심할 수 있으면 그 테스트셋으로
잰 숫자도 의심해야 합니다.** 그래서 두 방향으로 감사했습니다.

**감사 1 — 정답표는 자기 기준값에 비춰 정합했습니다.** 수치상 참 10/10,
일부러 틀림 45/45, 어긋난 라벨 0건. 문단에 적힌 금액이 기준값에 있는지,
증감 방향이 실제 변화와 맞는지를 파이썬으로 전부 계산했습니다.

**감사 2 — 그런데 그 기준값이 실제 공시와 무관했습니다.**

| | |
|---|---|
| 실제/가상 배율 중앙값 | **4.5배** |
| 실제의 0.5~2배 안에 드는 것 | **22%** (152개 조합 중 34개) |
| 최대 괴리 | **484배** (삼성전자 2025 영업이익: 가상 900억 vs 실제 43.6조) |

그래서 **이 테스트셋으로는 수치 판정 정확도를 잴 수 없습니다.** PIERROT는
실제 공시와 대조하므로 "수치상 참"으로 라벨된 문단도 올바르게 "모순"이라고
판정합니다. 두 판정이 어긋나는 것은 오류가 아니라 **서로 다른 세계를 재고
있다는 뜻**입니다. 라벨과 판정을 그냥 맞춰 정확도를 냈다면 의미 없는 숫자가
나왔을 것입니다.

**대신 수치와 무관한 구조적 함정만 골라 쟀습니다.** 숫자가 맞든 틀리든
검증기의 행동은 같아야 하기 때문입니다.

| 함정 | 건수 | 고치기 전 | 고친 뒤 |
|---|---|---|---|
| 회사명 없음 | 5 | 5/5 보류 | 5/5 보류 |
| 미래 전망 | 10 | 10/10 보류 | 10/10 보류 |
| 미래 단정 | 10 | 3 보류 / **7 사라짐** | **10/10 보류** |
| 모호한 기간 | 5 | 0 보류 / **5 판정해 버림** | **5/5 보류** |
| 평가 표현 | 5 | 0 보류 / **5 판정해 버림** | **5/5 보류** |

세 결함을 새로 찾아 고쳤습니다. 자세한 내용은 아래
[측정이 잡아낸 오류들](#측정이-잡아낸-오류들)에 있습니다.

## 직접 써 보기

### 내 글을 넣어 보기

```bash
.venv/Scripts/python.exe scripts/verify_text.py my_analysis.txt
.venv/Scripts/python.exe scripts/verify_text.py --text "삼성전자의 2024년 매출은 300조원이다"
```

넣기 전에 **대조 가능한 범위와 글에서 찾은 종목을 먼저 보여 주고 물어봅니다.**
범위 밖의 글이면 호출 비용만 쓰고 전부 '확인 불가'가 나오기 때문입니다.

### API 로 쓰기

```bash
.venv/Scripts/python.exe scripts/run_api.py
# 문서: http://127.0.0.1:8000/docs
```

```bash
curl -X POST http://127.0.0.1:8000/verify \
  -H "Content-Type: application/json" \
  -d '{"answer": "삼성전자는 2024년 3분기에 6조 1,879억 원의 영업이익을 기록했습니다."}'
```

```jsonc
{
  "claims": [{
    "text": "삼성전자는 2024년 3분기에 6조 1,879억 원의 영업이익을 기록했다",
    "verdict": "CONTRADICTED",          // 근거와 어긋남
    "confidence": "CALCULATED",         // 숫자를 직접 비교함 (추정이 아님)
    "reason": "실제 연결 9조 1,833억원 / 별도 4조 5,049억원, 주장 6조 1,879억원 ..."
  }],
  "annotated_answer": "삼성전자는 ... 기록했습니다. [모순]",
  "uncovered": [{                      // 주장이 하나도 안 나온 문장
    "text": "내년에도 좋은 흐름이 이어질 전망입니다.",
    "why": "전망·권고로 보입니다. 지금 참·거짓을 가릴 수 없습니다"
  }],
  "summary": { "contradicted": 1, "calculated": 1, "inferred": 0 },
  "usage": { "elapsed_seconds": 22.2, "cost_usd": 0.0, "llm_calls": 5 }
}
```

`uncovered`가 있는 이유는 **문장이 조용히 사라지면 안 되기 때문**입니다.
쪼개기 단계는 전망 문장을 일부러 버리는데, 버린 사실을 적지 않으면
읽는 사람은 그 문장이 검사를 통과한 줄 압니다.

| 엔드포인트 | 하는 일 |
|---|---|
| `GET /health` | 자료와 키가 준비됐는지 |
| `POST /verify` | 답변을 쪼개고 문장마다 판정 |
| `POST /verify/claim` | 문장 하나만 판정 |
| `GET /usage` | 이번 달 비용을 단계별로 |

`cost_usd`가 0인데 `llm_calls`가 5인 것은 **전부 캐시 적중**이라는 뜻입니다.
월 예산이 $5라 호출 하나가 얼마를 썼는지 응답에서 바로 보이게 했습니다.

# 기술 상세

여기부터는 구현에 관한 내용입니다.

## 판정의 성격을 구분합니다

같은 "모순"이라도 근거의 질이 다릅니다. 결과에 `confidence`를 붙여 나눕니다.

| 값 | 뜻 | 실측 |
|---|---|---|
| `CALCULATED` | 공시·주가 수치와 직접 대조. 차이를 숫자로 제시 | 39건 |
| `INFERRED` | 문장 뜻 비교(NLI)로 추정. **그대로 믿으면 안 됨** | 2건 |
| `NONE` | 판정하지 않음 | 53건 |

둘을 한 칸에 세면 "모순 41건"이지만 그중 2건은 근거 문장이 주장과 무관했습니다.
보고서를 읽는 사람이 그 차이를 알아야 합니다.

### 연결·별도가 엇갈리면 사유에 적습니다

기준을 밝히지 않은 주장은 **둘 중 하나라도 맞으면 인정**합니다. 어느 기준을
가리키는지 알 수 없는데 한쪽으로만 판정하면 맞는 주장을 틀렸다고 하게 됩니다.

다만 **한쪽만 맞았다는 사실 자체가 정보**이므로 사유에 덧붙입니다.

```
현대차 2026년 2분기 당기순이익
  연결 3조 2,503억 -> 2조 8,879억 (감소)
  별도 1조 3,513억 -> 3조   344억 (증가)   <- 주장과 일치

"... -> 별도 기준과 일치 (다만 연결 기준으로는 감소했습니다)"
```

보통 "현대차 순이익"이라고 하면 연결을 가리킵니다. 적어 두지 않으면
**연결 기준으로는 반대였다는 사실이 가려집니다.** 판정은 바꾸지 않고
사실만 덧붙이므로 지표도 흔들리지 않습니다.

## 문장 뜻 비교(NLI)는 왜 쓰지 않나

베이스라인으로만 둡니다. 나쁘다고 짐작한 게 아니라, **고칠 수 있는 나쁨인지**를
갈라내기 위해 NLI에게 **정답 근거를 직접 쥐여 주고** 측정했습니다.
검색 실패 0건, 방해 문장 0건인 조건입니다.

| 조건 | 재현율 | 오탐률 |
|---|---|---|
| 쉬운 문제 · 문장 형태 근거 | 99.0% | 0.0% |
| 어려운 문제 · 문장 형태 근거 | **7.7%** | **36.5%** |

정답을 쥐여 줘도 52건 중 4건만 잡습니다. 근거를 더 좋게 줬더니 **오탐만 늘었습니다.**
임계값을 0.5~0.9로 훑어도 재현율이 7.7%에 고정됩니다. 오류가 양방향 모두 고확신이라
어떤 선을 그어도 갈라지지 않기 때문입니다.

```
같은 값인데 표기가 다름   2,589,355억원  vs  258조 9,354억원  →  모순 0.999
크게 틀렸는데 통과        약 1조원       vs  1조 3,461억원    →  함의 0.998
```

**"LLM/모델이 식별하고 파이썬이 계산한다"**는 설계 원칙이 여기서 나왔습니다.

## 에이전트 — 담당을 다시 정합니다

LangGraph 상태 머신입니다. 문장 쪼개기 단계가 붙인 유형을 그대로 쓰지 않고
문장을 보고 다시 정합니다. 94건 중 **43건의 경로를 뒤집었습니다.**

| 원래 유형 | → 바뀐 담당 | 건수 | 효과 |
|---|---|---|---|
| 서술 | 미래 전망 | 14 | 검증 대상에서 분리 |
| 실적 수치 | 부문별 매출 | 9 | 전용 자료로 |
| 서술 | 실적 수치 | 8 | 뜻 비교 대신 숫자 대조로 |
| 서술 | 주가 | 5 | 뜻 비교 대신 주가 계산으로 |
| 나머지 | | 8 | |

**13건이 뜻 비교 대신 계산 경로로 돌아갔고** 그만큼 적발이 늘었습니다.
라우팅은 LLM이 아니라 **규칙**입니다. 세 갈래 분류에 호출 비용을 치를 이유가 없고,
규칙은 테스트로 고정할 수 있기 때문입니다.

## 문장 쪼개기를 두 단계로 나눴습니다

판정 못 한 문장 12건이 **"누가/언제가 빠져서"** 조회조차 못 한 것이었습니다.
원문에는 있던 정보입니다. 쪼개기 프롬프트에 "회사와 연도를 반드시 넣어라"를
더해 봤는데, **추출이 보수적으로 바뀌어 서술 문장을 놓쳤습니다.**

| 접근 | 문장 수 | 원문 커버리지 | 시점 없음 | 주체 없음 |
|---|---|---|---|---|
| 원래 | 91 | 83.2% | 33.0% | 7.7% |
| 프롬프트에 합침 | 79 | 74.5% | 19.0% | 0.0% |
| 더 강하게 | 74 | **71.7%** | 17.6% | 2.7% |
| **두 단계로 분리** | **94** | **83.9%** | **4.3%** | **0.0%** |

한 프롬프트에 "빠짐없이 뽑아라"와 "엄밀하게 다듬어라"를 같이 넣으면 하나가 눌립니다.
그래서 분리했고, **2단계는 다시 쓰기만 하고 문장을 지울 수 없습니다** —
개수가 달라지면 코드가 결과를 통째로 버립니다. 부탁 대신 구조로 막았습니다.

## 수집한 자료

검증 중에는 외부에 접속하지 않습니다. 수집과 검증을 분리해 **몇 달 뒤에도
같은 숫자가 나오게** 했습니다.

| 자료 | 규모 | 비고 |
|---|---|---|
| 주가 | 18,920행 | 20종목 2023-01~2026-11, 수정주가 + 원주가 |
| 재무 주요계정 | 7,750행 | **2022~2026**, 연결/별도, 계정 15종 |
| 부문별 매출 | 2,040행 | 사업보고서 60건의 표를 구조화 |
| 배당·추가 계정 | 446행 | 배당금, 주당순이익(EPS), 지배주주순이익 등 |
| 공시 본문 | 25,370문장 | 사업의 내용 · 경영진단 |

부문별 매출 표는 **합계를 재무제표 매출액과 대조**해 검수했습니다. 단위를 잘못 읽거나
열을 잘못 짚으면 여기서 걸립니다. 표 파싱은 눈으로 몇 개 보고 넘어가면 반드시 틀립니다.

재무는 **보고 싶은 기간보다 한 해 앞서** 받습니다. 증감은 전년 수치가 있어야
계산되기 때문입니다. 처음에 2023년부터 받았더니 "2023년에 매출이 증가했다" 류가
전부 확인 불가로 나왔습니다. 스냅샷의 첫 해는 기준으로만 쓰이고 그 해 자체의
증감은 판정하지 못합니다.

## 측정이 잡아낸 오류들

전부 합성 데이터로는 안 나오고 실제 데이터에 돌려야 보인 것들입니다.
하나씩 회귀 테스트로 고정했습니다.

| 증상 | 원인 |
|---|---|
| 일률 3% 허용 오차가 환각을 통과시킴 | 실제 최저가 371,000원인데 "36만원"이 **130원 차이로** 통과 |
| 수정주가를 당시 호가로 착각 | 20종목 중 3종목이 분할·합병으로 보정돼 있었음 |
| 수치를 말하지도 않은 문장이 모순 판정 | 파서가 빈 값을 0으로 채우고 그대로 비교 |
| 구간이 넓으면 아무 주장이나 통과 | "전년 동기간"이 연 단위로 해석돼 등락률 폭 63%p |
| 표의 열이 기간이 아니라 지역이었음 | 기아 보고서는 열이 국내·북중미·유럽 |
| 같은 계정명이 세 군데에 있었음 | "지배기업소유주지분"이 자본/순이익/포괄손익에 모두 존재 |
| 캐시가 옛 스키마 응답을 반환 | 스키마만 바꾸고 프롬프트를 그대로 둠 |
| 없는 회사를 지어내 판정 | 회사명 없는 글에 "SK하이닉스"를 채워 넣고 그 수치로 모순 판정 |
| 인과 문장을 방향 주장으로 읽음 | "매출 증가의 **원인은** ~이다"를 "매출이 증가했다"로 판정 |
| 최상급 주장을 방향으로 읽음 | "**역대 최대** 영업이익"을 "영업이익이 늘었다"로 판정 |
| 한 문장의 **앞부분만** 보고 통과 | "매출은 늘었으나 영업이익은 줄었다"에서 매출만 확인 |
| "**흑자 전환**"을 단순 증가로 취급 | 2024년에 이미 +4,602억 흑자인데 2025년 +7,320억을 보고 통과 |
| 숫자가 둘인 문장을 방향으로 읽음 | "2조에서 3조로 늘었다"에서 **적힌 숫자를 통째로 무시** (실제 0.58조 → 1.35조) |
| 문장 안의 **절이 사라짐** | 앞 절에 주장이 붙으면 뒤 절("2027년 역대 최대 달성")이 흔적 없이 증발 |
| 모호한 기간을 **연도로 바꿔치기** | "최근 매출"을 "2024년 매출"로. `최근`을 지워 추적조차 불가 |
| 평가 표현을 의미 비교로 판정 | "좋은 실적을 냈다" → 함의 0.998 / 모순 0.999 **동시에 높음** |

윗줄 다섯 건은 **참인 일부로 더 강한 주장을 통과시킨** 같은 패턴입니다.
"매출이 늘었다"는 참이지만 "그 원인은 X다", "역대 최대다", "영업이익은 줄었다",
"흑자로 돌아섰다", "2조에서 3조로"는 각각 더 강한 주장입니다.
일부만 확인하고 통과시키면 **거짓이 참이 됩니다.**

아랫줄 세 건은 성격이 다릅니다. **확인하지 않은 것을 확인한 것처럼 보이게 만든**
문제입니다. 절이 사라지면 읽는 사람은 그 주장이 검사를 통과한 줄 알고,
`최근`이 `2024년`으로 바뀌면 추측한 연도에 가장 믿을 만한 `CALCULATED` 등급이
붙습니다. 틀린 판정만큼 나쁩니다.

그리고 이들 중 여럿은 **프롬프트로 막으려다 실패한 뒤 코드 검사로 바꿔서** 고쳤습니다.
"답변에 없는 정보를 넣지 마십시오"라고 적어 둬도 지켜지지 않습니다.
지켜야 할 것은 검사해야 합니다.

### 틀린 판정만큼 나쁜 것: 아무것도 설명하지 못하는 사유

이 검증기에서 **확인 불가의 사유는 결과 그 자체**입니다. 무엇이 없어서 못 봤는지
적혀 있어야 다음에 무엇을 모을지 정할 수 있습니다. 함정 20건이 사유가 뭉개진
자리를 넷 더 찾아냈습니다. **판정은 맞았지만 사유가 틀렸거나 비어 있던 것들입니다.**

| 문장 | 전에 나오던 사유 | 지금 나오는 사유 |
|---|---|---|
| "2027년 매출 목표를 달성했다" | "부문별 실적 주장이 아닙니다" | "매출 목표는 재무제표 주요계정에 없습니다" |
| "6개 연도 중 가장 높은 수치" | "구체적인 수치가 없으므로 OTHER" | "수집 범위(2022년~) 안에서는 가장 큽니다. 그 이전 수치가 없어 확정할 수 없습니다" |
| "전년 대비 증가액은 1,000억 원" | "주장 **+1000.0%**" (단위가 다름) | "실제 증감액 5조 1,258억원, 주장 1,000억원" |
| "2027년 매출도 늘어날 전망입니다" | **아무 데도 나오지 않음** | "전망·권고로 보입니다. 지금 참·거짓을 가릴 수 없습니다" |

마지막 줄이 특히 중요합니다. 쪼개기 단계는 전망 문장을 **일부러 버립니다.**
그 자체는 옳지만, 버린 사실을 적지 않으면 읽는 사람은 그 문장이
**검사를 통과한 것인지 아예 보지 않은 것인지 구분할 수 없습니다.**
이제 `uncovered` 항목으로 사유와 함께 남깁니다.

같은 맥락에서 **비용이 항상 $0으로 보고되던 버그**도 여기서 드러났습니다.
20건을 돌리고 "$0.00000"이 찍혔는데 비용 로그는 $0.025 늘어 있었습니다.
비용 로거 인스턴스가 둘이어서 차이를 재는 쪽이 아무것도 못 보고 있었습니다.
**월 예산 $5를 지키려고 만든 장치가 아무것도 못 보고 있었던 것입니다.**

## 기술 구성

| 자리 | 사용 기술 | 실행 위치 |
|---|---|---|
| 답변 생성 | Ollama `gemma3:4b` | 로컬 서버 (무료) |
| 문장 쪼개기 / 파싱 | OpenAI `gpt-4o-mini` | OpenAI API |
| 에이전트 | LangChain + LangGraph | 로컬 |
| 검증 도구 | DART 공시 API, FinanceDataReader, pykrx, `Huffon/klue-roberta-base-nli` | 로컬 (무료) |
| 평가 | 직접 구축한 테스트셋 + 재현율 / 오탐률 / 커버리지 | 로컬 (순수 파이썬) |
| 서빙 | FastAPI | 로컬 |
| 운영 | 응답 캐시, 토큰·비용 로거 | 로컬 |

### 설계 원칙 세 가지

1. **LLM은 식별, 파이썬은 계산** — 문장을 쪼개고 뜻을 읽는 것만 LLM에 맡깁니다.
   숫자 비교, 날짜 해석, 허용 오차, 판정은 전부 파이썬입니다. 측정으로 정한 원칙입니다.
2. **평가 재현성** — `evaluation` 모듈은 LangChain에 의존하지 않습니다. 검증 중에는
   외부 조회를 하지 않고 로컬 스냅샷만 씁니다. 외부 사이트가 바뀌어도 과거 지표를
   다시 뽑을 수 있어야 하기 때문입니다.
3. **비용 통제** — 월 예산 $5. 응답 캐시와 비용 로거를 0단계부터 필수로 뒀습니다.
   누적 호출 15,898건 중 **72%가 캐시 적중**이고 실제 지출은 **$1.38**입니다.

| 3 | LangGraph 에이전트 | 담당 재분류 43건 |

4단계를 3단계보다 **먼저** 진행했습니다. 검증되지 않은 도구 위에 에이전트를 올리면
오류가 쌓이기 때문입니다.

테스트 **576개** 통과. 프롬프트나 판정 기준을 바꿀 때마다 4단계 지표를 다시 재서
100% / 0%가 유지되는지 확인합니다.

## 알려진 한계

1. **문장 뜻 비교는 여전히 믿을 수 없습니다.** 94건 중 NLI가 판정한 2건은 둘 다
   근거 문장이 주장과 무관했습니다. 그래서 `confidence`로 구분해 표시합니다.
   평가 표현("좋은 실적")은 아예 NLI로 보내지 않도록 막았습니다 —
   함의와 모순이 **동시에** 0.99를 넘어 어느 쪽으로 갈라져도 근거가 못 됩니다.
2. **검색이 병목입니다.** 어휘 기반이라 뜻이 같아도 표현이 다르면 못 찾습니다.
   "반도체 사업 부문 실적 개선"과 "DS 부문 영업이익 흑자 전환"은 겹치는 낱말이 0입니다.
3. **테스트셋이 실제 환각과 분포가 다릅니다.** 오류를 의도적으로 주입해 만들어
   라벨은 확실하지만 결이 다릅니다. 그래서 실제 답변 94건을 따로 돌려 커버리지를 별도로 냅니다.
   **남이 만든 테스트셋은 라벨부터 감사합니다.** 가상 샘플 100건은 라벨 자체는
   정합했지만 기준값이 실제 공시와 중앙값 4.5배 달라, 수치 정확도 측정에는
   쓸 수 없고 구조적 함정만 쓸 수 있었습니다(`scripts/audit_sample_answers.py`).
4. **유니버스가 20종목입니다.** 그 밖은 전부 확인 불가입니다. 측정 재현성을 위해
   고정해 둔 것이라, 넓히면 과거 지표를 다시 재야 합니다.
5. **금융 도메인에 맞춰져 있습니다.** 다른 도메인에 적용하려면 `tools` 모듈을
   교체해야 합니다. 파이프라인 구조 자체는 도메인에 독립적입니다.
6. **부문별 주장은 금액이 있어야 봅니다.** "전지 부문 매출이 늘었다"처럼 증감
   방향만 말한 부문 주장은 아직 판정하지 못합니다. 자료에는 연도별 수치가 있으니
   고칠 수 있는 한계입니다.
7. **"같은 수준"에는 애매한 구간이 있습니다.** 변동률 ±3% 안쪽이면 맞다고, ±10%를
   넘으면 틀렸다고 봅니다. 그 사이는 억지로 한쪽으로 몰지 않고 **실제 변동률을
   적어 확인 불가로 둡니다.** 가르지 못한 것을 가른 척하는 것보다 낫습니다.

## 실행 준비

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"

cp .env.example .env     # 실제 키를 채웁니다 (.env 는 커밋되지 않습니다)
```

Ollama는 원격 서버의 `127.0.0.1:11434`에만 바인딩되어 있어 SSH 터널이 필요합니다.

```bash
ssh -N -L 11434:127.0.0.1:11434 ai-server
```

### 동작 확인

```bash
.venv/Scripts/python.exe -m pytest              # 단위 테스트 (API 호출 없음, 과금 없음)
.venv/Scripts/python.exe scripts/check_setup.py # 실제 연결 확인 (약 $0.00001 과금)
```

`check_setup.py`는 네 가지를 실제로 실행합니다.
설정 로딩 → Ollama 응답 → OpenAI 호출 1회와 비용 기록 → 재호출 시 캐시 적중과 무과금.
