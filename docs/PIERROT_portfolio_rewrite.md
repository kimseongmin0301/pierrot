# 01 · AI 답변 검증 (PIERROT) · 판단 기준

## AI가 생성한 금융 답변을 검증하고, 검증기의 성능까지 평가했습니다

**내 역할:** 문제 정의 · 아키텍처 및 판정 정책 설계 · 평가 데이터 설계 · 결과 검수

**구현:** AI 코딩 에이전트 활용

PIERROT는 LLM이 생성한 금융 답변을 개별 주장으로 분리하고, DART 공시와 주가 데이터를 바탕으로 근거를 검증하는 시스템입니다. 단순히 오류를 탐지하는 기능을 구현하는 데 그치지 않고, 어떤 조건에서 판정이 신뢰할 만한지와 어떤 경우에 판단을 보류해야 하는지를 정량적으로 평가했습니다.

공시·주가 스냅샷으로 생성한 평가 데이터 500건에서 오류 탐지 재현율 100%, 오탐률 0%를 기록했습니다. 실제 LLM 답변에 대해서는 판정 가능 비율이 43.6%였으며, 판정하지 못한 원인을 분석해 개선 과제를 도출했습니다.

**처리 흐름:** AI 답변 → 주장 분해 → 원문 기반 맥락 보완 → 규칙 기반 라우팅 → 데이터 대조 → 판정 및 근거 제시

## 01. 문제 정의

LLM이 생성한 금융 답변에는 실제 공시와 다른 수치가 포함될 수 있습니다. 실험에서 모델은 삼성전자의 2024년 3분기 영업이익을 6조 1,879억 원으로 제시했으나, 공시상 연결 영업이익은 9조 1,833억 원이었습니다.

이러한 오류를 식별할 수 있도록 답변의 각 주장을 외부 근거와 대조하고, 검증 결과와 판정 사유를 함께 제공하는 시스템을 설계했습니다.

## 02. 설계 제약

월 API 비용을 5달러 이내로 제한하고, 동일한 데이터로 평가를 반복할 수 있도록 수집과 검증을 분리했습니다. 공시 및 주가 데이터는 사전에 수집한 스냅샷을 사용하며, LLM 호출 비용은 캐시와 사용량 로깅으로 관리합니다.

## 03. 핵심 설계 결정

LLM은 비정형 답변에서 주장을 추출하고 회사·시점·수치 등을 구조화하는 데 활용했습니다. 검증 경로는 규칙으로 선택하며, 재무·주가 수치의 계산과 비교는 Python으로 처리하도록 역할을 분리했습니다. 정량화하기 어려운 서술에는 NLI(자연어 추론)를 제한적으로 사용하고, 계산 기반 판정과 구분합니다.

NLI에 정답 근거를 직접 제공한 추가 실험에서도 어려운 평가 데이터의 오류 탐지 재현율은 7.7%에 머물렀습니다. 이를 근거로 수치 검증에는 의미 비교보다 직접 계산을 우선하는 구조를 채택했습니다.

## 04. 평가 설계

공시·주가 스냅샷에서 정상 주장과 오류를 주입한 주장을 생성해 평가 데이터 500건을 구성했습니다. 기본 표현 300건과 복잡한 수치·날짜 표현 200건으로 나누고, 도구 기반 검증, LLM 직접 판정, NLI 기반 판정을 동일한 데이터에서 비교했습니다.

재현율과 오탐률뿐 아니라 판정 가능 비율도 함께 측정해, 판단을 지나치게 보류하는 방식이 좋은 성능으로 해석되지 않도록 했습니다.

| 검증 방식 | 오류 탐지 재현율 | 오탐률 | 판정 가능 비율 |
|---|---:|---:|---:|
| PIERROT | 100% | 0% | 100% |
| LLM-as-judge | 46.2% | 31.1% | 67.5% |
| NLI | 15.4% | 45.3% | 66.0% |

*비교표는 어려운 평가 데이터 200건 기준입니다. PIERROT의 100% / 0%는 기본 평가 데이터 300건에서도 동일했습니다. 검증에 필요한 데이터가 확보된 조건의 결과이며, 실제 금융 답변 전체에 대한 정확도를 의미하지 않습니다.*

## 05. 측정 결과와 한계 분석

로컬 LLM이 생성한 금융 답변 10건에서 추출한 주장 94건을 별도로 검증했습니다. 41건이 모순으로 분류됐고, 이 중 39건은 수치 직접 대조, 2건은 NLI 기반 추론 결과였습니다. NLI 판정 2건은 관련성이 부족한 근거를 사용한 것으로 확인했습니다.

판정하지 못한 53건은 미래 전망·투자 권고, 데이터 부족, 검색 및 의미 비교의 한계 등으로 분류했습니다. 이를 통해 데이터 확충으로 개선할 수 있는 영역과 현재 검증 방식으로 판정하기 어려운 영역을 구분했습니다.

### 핵심 지표

- **100%** — 합성 평가 데이터 500건에서 오류 탐지 재현율
- **0%** — 동일 평가 데이터에서 정상 주장에 대한 오탐률
- **43.6%** — 실제 LLM 답변의 전체 주장 94건 기준 판정 가능 비율 (전망 제외 시 53.9%)
- **$1.38** — 누적 API 비용 (월 예산 $5, 캐시 적중률 72%)

측정 기록 기준일: 2026-11-20. 회귀 테스트 576개 통과 기록을 바탕으로 프롬프트와 판정 정책 변경 시 기존 성능을 재확인합니다.

## 핵심 사례 1 · 코드 기반 가드레일

### 프롬프트에 의존하던 제약을 코드에서 검증

주장 추출과 맥락 보완 과정에서 LLM이 원문 정보를 누락하거나 새로운 정보를 추가하는 문제가 발생했습니다. 프롬프트 수정만으로는 일관되게 방지하기 어려워 출력 검증 로직을 적용했습니다.

- **주장 누락:** 맥락 보완 전후의 주장 개수가 다르면 해당 출력을 거부합니다.
- **원문에 없는 회사명 생성:** 새롭게 추가된 회사명이 원문에 존재하는지 검사합니다.
- **복수 수치 누락:** 시작값과 종료값이 함께 제시된 주장은 단순 증감 방향으로 축소하지 않도록 규칙을 적용합니다.

이를 통해 반드시 준수해야 할 제약을 프롬프트에만 맡기지 않고, 코드와 회귀 테스트로 관리하도록 개선했습니다.

## 핵심 사례 2 · 실패 유형 분석과 평가 개선

### 일부 사실만으로 전체 주장을 인정하는 오류 개선

매출 증가의 원인, 역대 최대 실적, 흑자 전환과 같은 주장에는 단순 증감 여부 이상의 검증 조건이 필요합니다. 기존에는 일부 사실이 일치하면 전체 주장에 근거가 있다고 판정하는 문제가 있었습니다.

개별 오류를 공통 실패 유형으로 분류하고, 해당 유형을 포함한 문서 20건(주장 45건)으로 검증했습니다. 개선 후 판정 일치율은 91.1%(41/45)에서 97.8%(44/45)로 상승했으며, 거짓 주장에 근거가 있다고 판정한 사례는 2건에서 0건으로 줄었습니다. 동일 사례에 대한 개선 전후 결과이며, 미관측 데이터에 대한 일반화 성능은 아닙니다.

추가로 외부 가상 평가 데이터 100건의 라벨과 기준값을 검토했습니다. 가상 기준값은 실제 공시와 중앙값 기준 4.5배 차이가 있어 수치 정확도 평가에는 적합하지 않았습니다. 이에 회사명 누락, 미래 시점, 모호한 기간, 주관적 평가 등 구조적 검증에만 활용했습니다. 개선 후 해당 사례 35건에서 판단 보류 동작을 확인했습니다.

## 추가 설계 결정

- **판정 근거의 구분:** 수치 직접 대조와 NLI 기반 추론을 별도 신뢰 유형으로 표시합니다.
- **평가 우선 설계:** 검증 도구의 성능을 측정한 뒤 에이전트에 연결해 오류 전파를 줄였습니다.
- **판정 보류 사유 기록:** 데이터 부족, 검증 범위 초과, 모호한 표현 등을 구분해 후속 개선에 활용합니다.
- **검증되지 않은 원문 구간 추적:** 주장으로 추출되지 않은 문장과 절도 사유와 함께 남겨 검증 누락을 확인할 수 있도록 했습니다.
- **회계 기준 차이 표시:** 연결·별도 기준이 명시되지 않은 주장은 두 기준을 비교하고, 한쪽에만 일치할 경우 그 차이를 판정 사유에 기록합니다.
- **데이터 스냅샷 관리:** 국내 20종목의 재무제표, 주가, 부문별 매출 및 공시 본문을 사전에 수집해 동일한 데이터 기준으로 평가할 수 있도록 구성했습니다.

## 현재 한계 및 개선 방향

검증 범위는 국내 20종목과 확보한 공시·주가 스냅샷으로 제한됩니다. 현재 서술 검증은 어휘 기반 검색과 NLI에 의존하기 때문에 동일한 의미를 다른 표현으로 기술한 주장에 대한 근거 검색이 어렵습니다. 향후 검색 개선의 효과를 기존 평가 데이터와 별도 평가 데이터에서 확인할 필요가 있습니다.

이 프로젝트에서 중점을 둔 것은 모든 AI 답변을 판정하는 것이 아니라, 검증 결과의 신뢰 범위를 정의하고 판정할 수 없는 이유까지 추적할 수 있는 시스템을 설계하는 것입니다.
